# CPR Codex 糖果自检插件

**CPR（codex-proxy-rs）原生 Rust 插件**：把 CPA 平台上的 [`cpa-plugin-codex-candy-eval`](https://github.com/haowang02/cpa-plugin-codex-candy-eval)（Go + CGO 动态库）的检测能力，重写为运行在 CPR `gateway-plugin-sdk` 上的独立子进程插件，用于自查 Codex 账号是否“降智”、模型指纹是否被替换、以及模型在长输出与指令遵循上的退化。

> 本仓库是**魔改移植版**，不是上游原作者发布的产品。来源与许可见 [NOTICE.md](NOTICE.md) 与 [LICENSE](LICENSE)。

## 功能套件

界面顶部页签切换，四套件共用同一套模型调用链路（可指定账号、模型与推理强度）：

| 套件 | 用途 | 结果口径 |
| --- | --- | --- |
| **糖果测试** `candy` | 向账号发同一道题并比对标准答案，最直接的“降智”判据 | 答对 / 答错 / 请求出错 / 已跳过，按“模型+推理强度”单独统计正确率与最近 20 次分布 |
| **深度追踪** `modeltrace` | 按 ModelTrace 题库采集样本，与参考基线比对 | 最接近的候选模型与概率、家族概率、有效样本数；历史记录按题库 SHA-256 摘要归档 |
| **鹈鹕绘图** `pelican` | 无工具生成 SVG 自行车动画 | 直接渲染生成的动画页面，观察长输出与指令遵循是否退化 |
| **模型指纹** `fingerprint` | 多轮探针 + 基线比对，判断实际服务的模型与声明是否一致 | 当前版本页面**未提供入口**（引擎与管理路由保留，供后续启用） |

## 与上游的主要差异（魔改点）

- **运行时**：Go + CGO 动态库 → **纯 Rust 子进程插件**（Tokio 异步 IPC，`runtime: trustedProcess`），除宿主 ABI 外不依赖共享库，不需要与宿主同编译器/同 libc 构建。
- **账号来源**：CPR 通过 `account_facts` 暴露账号事实，插件直接读取，**不在插件内维护凭据文件**；读取失败时显式报错，不会伪装成“0 个账号”。
- **模型调用**：页面评测由插件后台执行器复用管理员预先创建的测试 Key 调用 CPR 标准 `/v1/responses`，不依赖页面 RPC 作用域，不读取上游账号 Token。旧同步接口继续使用官方 SDK。
- **推理强度语义**：空推理强度按上游原意**整键省略**（交回宿主与上游默认值），不发送空字符串。
- **前端**：单页内联打包（无外链脚本请求，适配宿主沙箱 CSP），对话框保留非模态 `show()` 兼容路径并按父页面实际可见区域定位；嵌入模式不使用视口最小高度，避免 iframe 自动高度反馈循环；运行期间持续轮询状态显示进度。
- **取消语义**：取消后立即放弃在途样本并结束状态机，不无限期等待上游响应。
- **工程化**：逐版本离线制品（官方 `cpr-plugin package`，含逐文件摘要）、页面契约测试与真实 IPC 帧契约测试。
- **历史持久化（v1.0.12+）**：官方状态 KV 分块写入（每块 16 KiB），双缓冲完整写入后才 CAS 提交索引；读取校验长度与 SHA-256，写入串行化，避免把 240 KiB 快照塞进 SDK 64 KiB 元数据帧。旧 `global` 键保留不改；每账号每套件最近 20 条及快照预算维持原规则。
- **恢复一致性（v1.0.13+）**：记录按稳定 ID 核验后合并；正文、样本或时间冲突会拒绝覆盖。开启 JSON 精确浮点往返，兼容已有记录的机器精度级舍入差异；无 ID 的糖果结果保留重复次数，防止把旧结果恢复成重复新记录。
- **后台评测（v1.1.0+）**：直接支持官方 CPR，无需修改或重编译宿主。启动确认后由插件进程持有任务，离开插件页面不停止评测；返回后恢复进度，主动停止会取消在途请求。

### 官方 CPR 上的后台评测

本修复分支的 `v1.7.2` 针对 CPR `3.33.x` 至 `3.35.x`，使用 CPR SDK `v3.35.1` 和 RPC 协议 7。原始 `v1.7.0` 仅适用于 CPR `3.32.x`，不要混用。

v1.7.x 使用官方 CPR `>= 3.33.0, < 3.36.0` 和插件 RPC v7。插件复用 CPR 中预先创建的共享测试 Key，不创建分组、不修改分组成员、不创建 Key，也不删除或调整现有资源。请在插件配置中填写 `test_key_id` 或唯一的 `test_key_name`，并确保该 Key 已授权需要测试的账号和分组。Key 必须启用；预算、并发和限流由管理员在 CPR 中统一管理。CPR `>= 3.31.0, < 3.32.0` 使用 v1.6.x（RPC v5）；CPR `>= 3.30.2, < 3.31.0` 使用 v1.5.x（RPC v5）；CPR `>= 3.29.7, < 3.30.0` 使用 v1.4.x（RPC v5）。v1.2.x / v1.3.x 使用 CPR `>= 3.29.1, < 3.29.7` 和 RPC v4；CPR 3.28.x 请使用 v1.1.3（RPC v2）。

插件不再为账号创建 Key，也不修改已有 Key 的预算、并发或限流。请在 CPR 的 Key 管理中按你的总量需求设置这些限制；Key 明文仅在执行器内存中使用，不传给页面或写入插件状态。

默认请求同一网络命名空间内的 `http://127.0.0.1:8080`。如果 CPR 使用其他监听地址，在插件配置中设置 `api_base_url`；仅接受回环 IP，不允许域名、认证、路径或查询参数。执行器禁用环境代理和重定向，避免把测试 Key 发到其他机器。

结果仍保存在 CPR 原生状态库。页面打开时由状态查询写入；没有任何页面时，由官方周期维护回调提交。模型执行不依赖维护回调的 30 秒调用期限。页面关闭不取消任务；停止或重启插件进程会结束在途任务，已有持久化历史保留。

`patches/` 保留的是 v1.0.14 的历史过渡方案，原生后台执行不使用这些补丁。请按上述协议版本选择插件与官方 CPR 镜像。

### 每小时自动测试糖果题（v1.3.0+）

在 CPR 的插件设置中开启 **每小时自动测试糖果题**（`hourly_candy_enabled`）。默认关闭；首次开启后在下一次官方维护回调中启动首轮，此后每隔 60 分钟调度一轮；关闭后再开启沿用已保存的调度时间，不重复上一轮。糖果页显示是否启用、模型、推理强度和下次调度时间。

- 每个启用账号每轮测试 1 次，默认 `gpt-6.1-sol / low`；可用 `hourly_candy_model`、`hourly_candy_effort` 调整，手动测试的选择不影响自动配置。
- 直接使用插件后台执行器；不需要页面常开、外部定时器、管理员凭据或宿主补丁。结果写入同一份糖果历史，沿用每账号最近 20 条的保留规则。
- 同一账号正在执行任意测试时跳过本轮，不中断手动任务；禁用账号不测试。自动任务也能通过原有停止按钮取消。
- 调度时间先写入原生状态库再发模型请求；保存失败不执行。重启不重复上一轮，停机跨过多轮后仅运行一轮，不密集补跑。调度准备失败会显示错误并等待下一轮。
- 官方维护回调按约 30 秒周期检查，实际启动可比页面所示计划时间稍晚。关闭开关停止后续调度，已有任务按原停止规则处理。

### 启动与通知契约

页面向四套件的运行路由发送 `POST`，查询参数为 `background=1`。成功返回 HTTP 202 和 `queued: true`，表示任务已交由插件后台执行，前端显示“已开始后台测试”，不把提交成功当成测试完成；进度和结果通过状态查询更新。

`started` 是本轮启动的账号数量，`skipped`、`unchecked`、`busy` 是账号标识数组。通知只显示计数，空数组不产生跳过告警。`unchecked` 表示未确认支持所选模型、实际已跳过。无 `background=1` 的旧同步调用保持执行结束后返回的原契约。

页面契约测试覆盖四套件的同步和后台响应、延迟确认、重复点击抑制、错误提示，以及停止请求的单账号 ID 参数。真实插件进程测试会让原作用域失效，核对后台采样、停止、维护提交和重启重读。

## 构建与测试

依赖：Rust 工具链、Node.js（页面契约测试）、与目标宿主协议匹配的官方 `cpr-plugin` CLI。v1.7.x 使用 CPR 3.32.0 的 RPC v6 打包器；v1.6.x 使用 CPR 3.31.0 的 RPC v5 打包器；v1.5.x 使用 CPR 3.30.2 的 RPC v5 打包器；v1.4.x 使用 CPR 3.29.7 的 RPC v5 打包器；v1.2.x / v1.3.x 使用 RPC v4 打包器。可用 `CPR_PLUGIN_CLI` 指定 CLI 路径；旧版 CLI 会拒绝新版清单。

```bash
# 单元与契约测试（含握手、驱动、账号契约、模型执行契约）
cargo test --offline --locked
# 使用 Rustup 的当前工具链；不要使用无法解析当前锁文件的系统旧 Cargo。
# 发布脚本默认优先使用 $HOME/.cargo/bin/cargo。

# 页面契约测试：在 jsdom 中校验内联资源、沙箱桥调用与交互断言
npm install            # 首次需要 jsdom 与 css-tree
node tests/check-page.mjs .

# 构建并打包离线制品（自动跑 fmt/test/页面校验/内联打包/release 构建）
bash tools/package-release.sh
# 输出：dist/native-<version>/nmbb.codex-candy-eval-<version>-x86_64-unknown-linux-gnu.tar.gz
```

### 浏览器布局回归（v1.0.10）

`jsdom` 不计算真实布局，不能证明 iframe 高度或弹窗位置稳定。使用 `agent-browser` 打开真实宿主插件页后，可在仅绑定回环的脱敏联调环境中执行：

```bash
python3 -m unittest discover -s tests -p 'test_browser_proxy.py'
# 额外依赖：websocket-client；端口取 agent-browser 管理的诊断 Chrome CDP 监听端口
python3 tests/check-browser-layout.py --port <cdp-port>
```

检查包括连续高度采样、ModelTrace/鹈鹕详情各三次开关、弹窗完整位于父页面可见区域、遮罩释放与账号页导航。它只读取既有记录，不启动模型评测；`--candidate` 仅在该诊断浏览器 DOM 中注入本地候选样式与弹窗逻辑，不修改线上制品。自动化覆盖不替代用户设备的交互验收。

> `sandbox="allow-scripts"` 并不禁止 HTML `<dialog>.showModal()`。`allow-modals` 约束的是 `alert`、`confirm`、`prompt` 等浏览器模态 API，不应据此推断 `<dialog>` 会抛权限异常。

## 安装与升级

v1.7.x 对应官方 CPR `>= 3.32.0, < 3.33.0`（RPC v6）；v1.6.x 对应官方 CPR `>= 3.31.0, < 3.32.0`（RPC v5）；v1.5.x 对应官方 CPR `>= 3.30.2, < 3.31.0`（RPC v5）；v1.4.x 对应官方 CPR `>= 3.29.7, < 3.30.0`（RPC v5）；v1.2.x / v1.3.x 对应 CPR `>= 3.29.1, < 3.29.7`（RPC v4）；CPR 3.28.x 使用 v1.1.3（RPC v2）。均无需宿主补丁，跨协议升级须同时升级宿主与插件。

1. 通过 CPR 管理接口上传制品：`POST /api/admin/plugins/artifacts/upload`；
2. 用 `switch-version` 把既有实例原子切换到新版本（实例 ID 不变，状态与历史记录保留）；
3. 校验实例状态：`running: true`、无 `loadError`、无兼容性警告，资源与路由数量符合预期；
4. 异常时恢复与宿主 RPC 协议匹配的制品。没有数据库或状态格式变更时，配套回退旧宿主与旧制品：先切回兼容制品，再更新实例配置和启停状态，避免旧宿主拒绝新版制品。涉及数据库迁移时，先保全升级后数据，再使用已验证备份恢复。v1.0.14 依赖旧宿主补丁，不能在官方镜像上单独降级到该版。**跨 v1.0.12 状态格式降级必须同时恢复升级前插件状态备份及配额，不能只切旧二进制**：新版使用多键双缓冲，状态配额为 40 条 / 2 MiB，旧版仅 10 条 / 256 KiB。恢复操作应先核对备份和目标实例。

正常安装无需额外服务。首次使用前，请在 CPR 中创建一个覆盖目标账号和分组的测试 Key，然后在插件配置中填写其 ID 或唯一名称；插件只读取并复用该 Key，不会产生按账号拆分的冗余资源。

## 目录结构

```
src/      插件实现：app 入口、command 指令分发、management 管理路由、host_calls 宿主 IPC、
          state 状态机与合并恢复、storage 原生 KV 分块快照、hourly 小时调度、background 后台执行、execution 回环执行器、四套件与 runs 调度
web/      前端界面：ui.html 单页（构建时内联全部脚本）、app/catalog/components 等模块、vendor 第三方库
data/     编译期嵌入的题面与基线（codex_context、指纹探针与基线、ModelTrace 题库）
tests/    Rust 契约测试 + jsdom 页面契约 + Chrome OOPIF 几何回归 + 代理认证/脱敏测试 + routes.json 路由清单
tools/    前端构建、CSS 资源提取与离线打包
```

`data/` 由 `include_bytes!` / `include_str!` 在编译期嵌入二进制，属于构建必需品。
